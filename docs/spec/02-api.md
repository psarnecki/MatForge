# 02. API

## 1. Conventions

- Base path `/api`. JSON, camelCase. Enums as strings. Dates `YYYY-MM-DD`.
- All endpoints require authentication **except** register, login, `/health`, and the OpenAPI document.
- Unauthenticated calls return **`401`** (never a redirect).
- Controllers are thin: they call one service method and return the result. Logic lives in `Application` services.
- **Errors** use ProblemDetails (RFC 9457):

| Situation | Status | Body |
|---|---|---|
| Validation failed | 400 | `ValidationProblemDetails` with an `errors` dictionary |
| Not found, or belongs to another user | 404 | `ProblemDetails` |
| Conflict (e.g. club in use, duplicate name) | 409 | `ProblemDetails` with a human-readable `detail` |
| Not authenticated | 401 | empty or `ProblemDetails` |
| Unexpected | 500 | `ProblemDetails`, no stack trace |

- Services throw `NotFoundException`, `ConflictException`, `BadRequestException(errors)`. One global `IExceptionHandler` maps them to the table above.
- **Validation:** DataAnnotations for trivial single-field rules (`Required`, `StringLength`, `Range`); FluentValidation for cross-field rules. One reusable filter runs validators before the action and produces the same 400 format. The same rule is never written twice.
- Create returns `201` with `Location` and the created resource. Update returns `200` with the updated resource. Delete returns `204`.
- Update (`PUT`) **replaces the whole resource**, including child lists (rounds, fights).
- Lists are not paginated (D-18).
- The OpenAPI document is generated by `Microsoft.AspNetCore.OpenApi` at `/openapi/v1.json`; Swagger UI comes from the `Swashbuckle.AspNetCore.SwaggerUI` package at `/swagger` (Development and Docker only).
- Health: `GET /health` returns `200` when the API can reach the database.

## 2. Auth and account

Identity API endpoints are mapped under `/api/auth` (`MapGroup("/api/auth").MapIdentityApi<AppUser>()`) with cookie authentication.

| Method | Path | Notes |
|---|---|---|
| POST | `/api/auth/register` | `{ email, password }`. Password rules are the ASP.NET Core Identity defaults (at least 6 characters, one uppercase letter, one lowercase letter, one digit, and one non-alphanumeric character); the server's error messages are shown in the form. |
| POST | `/api/auth/login?useCookies=true` | `{ email, password }`. Sets an HttpOnly cookie. |
| POST | `/api/auth/logout` | **Custom endpoint**: the Identity API endpoints of .NET 8/9 have no logout (the Microsoft docs show a small custom one calling `SignInManager.SignOutAsync()`). If the installed version has a built-in one, use it instead. Signs out. `204`. |
| GET | `/api/me` | `{ id, email, firstName, lastName, clubs[], belts[] }` |
| PUT | `/api/me` | `{ firstName, lastName }` |
| DELETE | `/api/me` | Deletes the account and all data. `204`. |

Registration in the UI is a chain: register → login → `PUT /api/me` (names). If the chain breaks, the profile page lets the user finish.

Cookie settings: HttpOnly, `SameSite=Lax`, `Secure` when the request is HTTPS. Account e-mail confirmation is disabled. Unused Identity endpoints (2FA, refresh, reset) may stay mapped; they are not used by the UI.

## 5. Training sessions

| Method | Path | Notes |
|---|---|---|
| GET | `/api/sessions?from=&to=&kind=` | `from` and `to` required (max range 400 days). Returns `SessionSummary[]` sorted by date, then id. |
| GET | `/api/sessions/{id}` | Full session with rounds |
| POST | `/api/sessions` | Creates session with rounds |
| PUT | `/api/sessions/{id}` | Replaces session and rounds |
| DELETE | `/api/sessions/{id}` | |

Request (flat, nullable fields by `kind`; rules in `01-domain-model.md` 4.4; rounds are accepted only when the character allows them):

```json
{
  "kind": "Grappling",
  "date": "2026-10-20",
  "durationMinutes": 90,
  "feeling": 4,
  "notes": "Half guard passing.",
  "disciplineId": 1,
  "formatId": 2,
  "characterId": 4,
  "clubId": 3,
  "activityTypeId": null,
  "rounds": [
    { "result": "Win",  "techniqueId": 12, "positionId": 5, "notes": null },
    { "result": "Loss", "techniqueId": 3,  "positionId": null, "notes": null },
    { "result": "Draw", "techniqueId": null, "positionId": null, "notes": null }
  ]
}
```

`Session` response = the request plus `id`. `SessionSummary` = `id, kind, date, durationMinutes, feeling, disciplineId, formatId, characterId, clubId, activityTypeId, roundsCount, wins, losses, draws` (no round details).

## 10. Analytics

`from` and `to` are optional: an omitted `from` means the date of the user's earliest session or competition (the dashboard's "All time"), but never later than `to`; an omitted `to` means today. `from ≤ to`, and `from` is not earlier than 2000-01-01. If the user has no data, both default to today. Response shapes and formulas: `03-analytics.md`.

| Method | Path | Extra query |
|---|---|---|
| GET | `/api/analytics/overview` | |
| GET | `/api/analytics/sparring` | `disciplineId`, `formatId` (optional) |
| GET | `/api/analytics/competitions` | `disciplineId`, `formatId` (optional) |
| GET | `/api/analytics/insights` | `disciplineId`, `formatId` (optional; apply to both the training and the competition side) |

## 11. Security notes (also material for the thesis)

- Passwords are hashed by Identity. Lockout is enabled with default settings.
- Cookies are HttpOnly; the API is same-origin and accepts JSON only, with `SameSite=Lax`. A dedicated anti-forgery token is out of scope; documented as a known limitation.
- Every query is filtered by the current user (global query filter) and verified by isolation tests.
- No secrets in Git: SQL password and other settings come from `.env`.
